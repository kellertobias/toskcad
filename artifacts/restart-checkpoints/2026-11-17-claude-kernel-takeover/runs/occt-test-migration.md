# OCCT test migration (workspace run 96cbc320, category a)

Branch `claude/occt-test-migration-2d2b5c`, based on `afaabb7a` (integration branch after merging main).
Scope: the 146 tests that failed with `OpenCascade is unavailable in this build` in
`runs/workspace-96cbc320/summary.json` (`classification.a_requires_occt`).
Only test code changed, plus the generator example `crates/multicad-app/examples/front_panel_demo.rs`, which now selects the Rust DXF backend explicitly.
Production stays OCCT-free.

## Result

| category | count | meaning |
|---|---|---|
| 1: legacy OCCT test, covered by an existing Rust test | 8 | deleted (7) or rewritten (1); the covering test is cited per row |
| 2: re-pointed to the Rust API/backend | 101 | ported, every assertion kept, **all pass** at HEAD |
| 3: real missing Rust capability | 31 | ported to the Rust path where possible; each now fails with the actual Rust refusal (one exception: the worker revolve, see gap 10) |
| oracle loss (no capability gap) | 6 | Rust builds the part; the test's only oracle was the OCCT build and no independent closed form exists. The test is left at its original form, so it still fails on the OCCT stub |

Where a test compared Rust output with an OCCT build, the OCCT side is replaced by an independent expectation derived from the saved document or the test's authored dimensions (analytic volumes, areas, bounds, frames, weld records). The same or tighter tolerances apply. **No value is pinned to current Rust output.**

Accepted judgement calls (see the rows):
- `rounded_threads.rs` / `knuckle_threads.rs` `material()`: Rust has no exact Boolean or overlap volume on rounded thread bodies (`rust_occupied_overlap_volume` → "Rust planar Boolean requires certified positive convex material pieces"). The OCCT cube-intersection fraction is replaced by exact point classification at the cube centre and 8 corners, requiring all or none. Each cube lies farther from the expected boundary than its half-diagonal, so the old fraction was 0 or 1. The proxy is documented in the helper as not exact.
- Rust face-role names differ from OCCT (single root band instead of `root/lower` + `root/upper`; `thread/rounded/*`). Tests assert the Rust names. Old saved references to the OCCT names will not resolve.
- `edge_treatment.rs`: the Rust cone apex is a vertex, not a degenerate edge. Renamed to `cone_apex_is_a_vertex_not_a_degenerate_edge_and_is_rejected_explicitly`; the apex fillet is still refused and the source stays unchanged.
- `rust_backend.rs::directed_draft…`: Rust now builds the two-sided draft that the test expected to be refused; the volume is checked against the analytic sum of the two halves.
- `connection_root_retry_factory.rs`: the OCCT owner-thread factory counters have no Rust counterpart, so this is category 1. The test still checks the validated geometry and owner rebinding.

## Category 3: missing Rust capabilities, by user impact

1. **Booleans on non-prismatic or rotated Rust bodies** (`orthogonal Boolean: Rust orthogonal Boolean requires a rectilinear prism or result aligned to world axes`). This blocks Model Cut/Join/Intersect against gears, worms, bevel gears, tapered/NPT/BSPT/rounded threads and rotated tools.
   - Shipped examples are affected: `welded-workbench.tcd` cannot rebuild (feature "Bore sliding handle"), and the Drawings preview of `apartment.tcd` fails.
   - Tests: `cabinetry::rust_bundled_workbench…`, app `drawings::cold_apartment_plan_preview…`, `drawings::cold_expanded_apartment_plan_preview`, kernel `gears` ×4, `internal_gears` ×1, `spherical_bevel::both_root_branches…`, `worm_gears` ×4, `axial_pipe_threads` ×1, `tapered_rounded_threads` ×1, `threads::custom_conical…`, `rounded_threads::rounded_crest…`.
   - Material checks on BSPT `faces()` also refuse ("Retained source proof failed: Limit").
   - The same workbench refusal now also fails two app tests that were not in the 96cbc320 run: `modeling::tests::rust_model_worker_publishes_all_bundled_project_scenes` (apartment.tcd pins the workbench symbol) and `drawings::tests::rust_worker_opens_and_restores_the_saved_apartment_isometric`. Neither test nor any production code changed on this branch, so they come from the workbench vise brought in by the main merge (`afaabb7a`).
2. **Gear-to-gear overlap volume and `intersect_parallel`** (`This operation is unavailable for the Rust solid`). Motion interference reports a yes/no certificate but no overlap volume. Helical half-tooth wrong phase returns Unresolved. Test: `worm_gears::parallel_intersection…`, and the volume part of `worm_gears::conjugate_pair…` and `gears::compatible_pairs…`.
3. **STEP round trip of Rust-written gear STEP.** Re-import fails for the hubbed spur and spherical bevel ("Imported boundary is not a valid closed solid") and for the herringbone ("Rust STEP import requires a supported analytic solid in millimeters"). Export fails for a revolved cone with its apex on the axis ("…one closed exterior shell per solid"). This affects Export → STEP and re-Import of gear designs. Tests: `gears::larger_teeth…`, `spherical_bevel::zero_bore…`, `spherical_bevel::directional_native_flux…`.
4. **Sketch profiles Rust cannot extrude or loft.** Affects Sketch → Extrude/Loft. Tests: `curves::rational_solid_step_roundtrip…`, `spline_edits::exact_segment_hits…`, `curves::mixed_true_arcs…`, `advanced_profiles::loft_authored_sections…`.
   - Rational splines: "This rational spline profile cannot yet be extruded".
   - Mixed arc + degree-1 spline + line outlines with a circular hole: "Authored spline section could not be certified: Unresolved".
   - Smooth lofts through 3 or more sections: "Rust smooth polygon loft requires all stations on the same straight transition".
5. **Rounded receiving threads in pattern or connection-member stock** ("Receiving stock cannot preserve an unambiguous authored attachment chart"). Affects the Thread feature on member stock. Test: `rounded_threads::blind_and_through_rounded_receivers…`.
6. **Phillips cosmetic screw envelope** ("Rust cosmetic screws support external hex heads or socket-cap and straight countersunk heads with flat hex sockets"). Affects switching a Phillips screw to the cosmetic representation via MCP/UI `set_mechanical_part`. Test: mcp `screw_profiles::native_profile_previews…`.
7. **Coincident Boolean drops the opposing inherited generator frame** (`Coincident Boolean inherited the opposite generator frame`). Attachments saved on such frames may resolve with a mirrored V. Test: `terminations::signed_face_offset…`.
8. **Formed-sheet touching-flange diagnosis.** Rust refuses the export but says "Rust formed sheet requires one full-length bend or two opposite full-length bends without reliefs" instead of naming the touching flanges. Sheet editing and DXF export give a generic message. Test: `sheet_dxf::developed_sheet_dxf_reopens…`.
9. **Fine knuckle manufacturing mesh**: 1 µm deflection exceeds the triangle budget ("Rust tessellation exceeds the triangle budget"). Affects print and mesh export of fine knuckle threads. Test: `knuckle_threads::small_knuckle…`.
10. **Kernel worker `GeometryOperation::NamedRevolve`** still calls the OCCT stub in production code (`crates/multicad-kernel/src/worker.rs:743`). Only kernel tests and `multicad-app/examples/viewport_review` use the worker program API, so no shipped UI workflow is affected. This is the one test still failing with the OCCT message: `revolve::revolve_worker_exports_only_current_owner_thread_keys`. Fixing it means mapping the operation to `rust_revolve_curved_profile_named`.

## Oracle loss (6): Rust builds the part, but there is no independent oracle
`rust_curved_drawer`, `rust_curved_drawer_cut`, `rust_drawer_axial_cut`, `rust_drawer_bosses`, `rust_drawer_coupon`, `rust_planar_drawer`.
- About 20 joined operands overlap: sloped rims, gussets, and quarter-round fillets crossing along elliptic edges.
- Surface area through the fillet–fillet intersections has no closed form.
- An exact volume would need pairwise and triple overlap integrals.
- The tests keep their original Rust-vs-OCCT comparison and fail on the OCCT stub. They need an independent exact-overlap evaluator (the start is `crates/multicad-model/tests/support/axis_solids.rs`, which handles the rack) or a product decision.

In the four ported gear files, five refusal tests now point at Rust and pass.
